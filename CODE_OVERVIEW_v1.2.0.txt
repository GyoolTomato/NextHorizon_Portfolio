NextHorizon v1.2.0 전투 코드 핵심 가이드
==========================================

이 문서는 v1.2.0에서 추가된 전투 코드를 빠르게 검토하기 위한 포트폴리오 설명서입니다.
릴리즈 변경사항 전체가 아니라 전투 구조를 이해하는 데 필요한 코드만 선별했습니다.


1. 한눈에 보는 전투 흐름
-------------------------

스테이지·캐릭터 선택
    → 전투 데이터 초기화
    → 플레이어 생성
    → 시간·위치 기반 적 스폰
    → 타겟 탐색
    → 이동·일반 공격·투사체 충돌
    → 회피·치명타·피해·사망 처리
    → 제한 시간 또는 전멸 조건으로 승패 판정
    → 서버에 클리어 결과 전송
    → 별·재화·장비 보상 표시

전투 씬의 큰 흐름과 캐릭터 한 명의 행동 흐름을 각각 상태 머신으로 분리했습니다.

- 전투 상태: Ready → Playing ↔ Pause → Finish
- 캐릭터 상태: Idle ↔ Running → Attack → Idle / Die

스킬 상태의 틀은 존재하지만 v1.2.0에는 실제 스킬 발동 로직이 포함되어 있지 않습니다.


2. 가장 먼저 볼 핵심 코드
--------------------------

[1] 전투 전체 상태 관리

경로:
- Scripts/UI/2_Play/PlayScene.cs
- Scripts/UI/2_Play/FSM/PlayState_Ready.cs
- Scripts/UI/2_Play/FSM/PlayState_Playing.cs
- Scripts/UI/2_Play/FSM/PlayState_Pause.cs
- Scripts/UI/2_Play/FSM/PlayState_Finish.cs

확인할 내용:
- PlayScene.ChangeState(): 전투 상태 전환과 Enter/Exit 호출
- PlayState_Ready.Enter(): 매니저, 제한 시간, 플레이어와 전투 UI 초기화
- PlayState_Playing.Update(): 타이머, 적 스폰, 피해 처리와 종료 조건 관리
- PlayState_Finish.Enter(): 전투 정지, 서버 클리어 요청과 결과 UI 연결

핵심 이유:
전투 진행 코드를 하나의 Update에 모두 넣지 않고 준비·진행·정지·종료의 책임을 나눴습니다.
전투 흐름을 가장 빠르게 파악할 수 있는 시작점입니다.


[2] 스테이지 전투 데이터와 적 스폰

경로:
- Scripts/_Common/GameData/GameData_InGame.cs
- Scripts/_Common/Tables/_701_StageMonster.cs
- Scripts/InGame/Map.cs

확인할 내용:
- GameData_InGame.Init(): 선택 캐릭터와 스테이지 몬스터 데이터를 전투 데이터로 변환
- SpawnPlayer(), SpawnCharacter(): 진영별 캐릭터 생성과 활성 목록 관리
- PlayState_Playing.Spawn(): 스폰 지점·등장 시간·쿨타임에 따른 순차 생성
- Map.GetSpawnPoint(): 테이블의 스폰 지점과 실제 월드 좌표 연결

핵심 이유:
적 구성과 등장 순서를 코드에 직접 작성하지 않고 테이블 데이터로 분리했습니다.
같은 전투 로직을 유지하면서 스테이지별 몬스터·수량·위치·시간을 변경할 수 있습니다.


[3] 캐릭터 상태 머신

경로:
- Scripts/InGame/Character/Character.cs
- Scripts/InGame/Character/State/CharacterState.cs
- Scripts/InGame/Character/State/CharacterState_Idle.cs
- Scripts/InGame/Character/State/CharacterState_Run.cs
- Scripts/InGame/Character/State/CharacterState_Attack.cs
- Scripts/InGame/Character/State/CharacterState_Die.cs

확인할 내용:
- Character.ChangeState(): 행동 상태의 Exit·교체·Enter 순서 관리
- CharacterState_Idle.Update(): 타겟 확인과 공격·이동 상태 결정
- CharacterState_Run.Update(): 공격 가능 거리까지 적 방향으로 이동
- CharacterState_Attack.Update(): 공격 지연과 다음 상태 전환
- Character.Damage(), DoDie(), Dead(): HP 감소부터 사망·목록 제거까지의 흐름

핵심 이유:
이동, 공격과 사망을 독립된 상태로 분리해 행동 추가와 수정의 영향을 줄였습니다.
애니메이션도 상태 진입 시점에 함께 전환되도록 연결했습니다.


[4] 전투 능력치와 피해 계산

경로:
- Scripts/InGame/Character/CharacterStats.cs
- Scripts/InGame/Manager/Manager_Damage.cs
- Scripts/UI/1_Game/Manager/Manager_Character.cs

확인할 내용:
- CharacterStats.Init(): 캐릭터 성장 수치와 장비가 반영된 전투 능력치 초기화
- Manager_Damage.AddDamage(): 회피 판정, 공격력·방어력 계산과 치명타 적용
- Manager_Damage.Update(): 대기 중인 피해 요청을 순서대로 실제 HP에 반영
- Manager_Character.GetTotalStat(): 캐릭터 기본·레벨·장비 능력치 통합

기본 계산 흐름:

1) 대상의 회피와 공격자의 명중 수치로 회피 여부 판정
2) (공격력 - 방어력) × 공격 배율로 기본 피해 계산
3) 치명타 확률에 성공하면 치명타 피해 배율 적용
4) 계산된 피해를 큐에 넣고 전투 갱신 시점에 적용

핵심 이유:
공격 행동과 수치 계산을 분리했습니다. 공격자는 피해 요청만 만들고 실제 계산과 적용은
Manager_Damage가 담당하므로 이후 스킬 배율이나 추가 피해 규칙을 확장할 기반이 됩니다.


[5] 타겟 탐색

경로:
- Scripts/InGame/Manager/Manager_SelectTarget.cs

확인할 내용:
- GetEnemyNearest(): 현재 진영의 반대편에서 가장 가까운 생존 대상 검색
- GetEnemiesNearest(): 거리순으로 여러 대상을 제한된 수만큼 검색
- IsInvalidTarget(): 비활성·사망·자기 자신을 후보에서 제외

핵심 이유:
타겟 선택을 캐릭터 상태 코드에서 분리했습니다. 단일 대상 일반 공격뿐 아니라 향후 다중 대상
스킬에서도 같은 탐색 규칙을 재사용할 수 있도록 구성했습니다.


[6] 투사체와 오브젝트 풀링

확인할 내용:

- Projectile.Init(), Update(), OnTriggerEnter(): 목표 위치 이동, 충돌 검사와 피해 요청

- RemoveCharacter(), RemoveProjectile(): 비활성화한 객체를 키별 풀에 반환

적과 탄환이 계속 생성되는 전투에서 Instantiate/Destroy 호출을 줄이기 위한 구조입니다.

확인할 내용:

- Manager_Playing.SetBattleResult(): 전멸 여부와 남은 시간에 따른 0~3단계 결과 계산

서버 연동:
- NextHorizonServer/server.js의 POST /api/stage/clear
- 서버가 스테이지 테이블을 다시 조회해 재화·방어구·무기 보상을 지급
- 이전 기록보다 높은 별 조건은 유지하고 클리어 횟수는 누적
- 보상 지급과 클리어 기록 갱신을 하나의 DB 트랜잭션으로 처리

핵심 이유:
전투 연출이 끝난 뒤 보상을 클라이언트에서 임의 생성하지 않고 서버 응답을 기준으로 결과 화면과
인벤토리를 갱신합니다.


3. 코드에서 확인할 핵심 설계 포인트
-----------------------------------

가. 두 단계 상태 머신
- 전투 전체 상태와 캐릭터 행동 상태를 별도로 관리합니다.
- 씬 흐름과 개별 유닛 행동이 서로 과도하게 의존하지 않도록 분리했습니다.

나. 데이터 기반 전투 구성
- 몬스터, 스폰 지점, 등장 시간, 캐릭터 능력치와 투사체 설정을 테이블에서 읽습니다.
- 스테이지 구성을 변경할 때 전투 코드 자체를 수정하는 범위를 줄였습니다.

다. 역할별 매니저 분리
- Manager_SelectTarget: 대상 검색
- Manager_Damage: 피해 계산과 적용
- Manager_InGamePool: 객체 생성과 재사용
- Manager_Playing: 맵·카메라·전투 결과

라. 클라이언트와 서버의 역할 분리
- 클라이언트: 실시간 전투, 입력, 연출과 승패 표시
- 서버: 스테이지 데이터 검증, 별 기록, 재화·장비 지급과 영속화

마. 확장 지점 확보
- 다중 대상 탐색 메서드
- CharacterState_Skill 상태 틀
- 공격 배율을 받는 피해 계산
- 테이블 기반 투사체

현재 빠져 있는 스킬 전투를 이후 추가할 수 있도록 필요한 연결 지점을 미리 분리했습니다.


4. 5분 검토 권장 순서
----------------------

1) Scripts/UI/2_Play/PlayScene.cs
   전투 상태가 어떻게 전환되는지 확인합니다.

2) Scripts/UI/2_Play/FSM/PlayState_Playing.cs
   타이머, 스폰, 승패 판정의 전체 전투 루프를 확인합니다.

3) Scripts/InGame/Character/Character.cs
   캐릭터 상태 전환, 공격, 피격과 사망 진입점을 확인합니다.

4) Scripts/InGame/Character/State/CharacterState_Idle.cs
   타겟 탐색 결과가 이동과 일반 공격으로 이어지는 과정을 확인합니다.

5) Scripts/InGame/Manager/Manager_Damage.cs
   회피·방어·치명타가 피해로 계산되는 과정을 확인합니다.

6) Scripts/InGame/Projectile/Projectile.cs
   공격이 실제 충돌과 피해 요청으로 연결되는 과정을 확인합니다.

7) Scripts/UI/2_Play/FSM/PlayState_Finish.cs
   승리 결과가 서버 보상과 결과 화면으로 이어지는 과정을 확인합니다.


5. 현재 구현 범위와 한계
------------------------

- v1.2.0은 일반 공격 중심의 기본 전투 구조입니다.
- 액티브·패시브 스킬의 실제 전투 효과와 발동 로직은 포함되어 있지 않습니다.
- 적 이동은 플레이어를 향한 직선 이동이며 길 찾기와 장애물 회피는 포함하지 않았습니다.
- 실시간 전투 판정은 클라이언트에서 수행합니다.
- 서버는 스테이지와 보상 데이터를 검증하지만 전투 과정 자체를 재현하거나 검증하지 않습니다.
- 현재 구조는 포트폴리오 데모에 맞춘 것이며 상용 서비스에서는 결과 위변조 방지 검증이 추가로 필요합니다.


6. AI 활용 범위
---------------

Codex를 이용해 전투 관련 저장소와 데이터 흐름을 분석하고, 상태 머신·타겟 탐색·피해 계산·
투사체·오브젝트 풀링·서버 보상 연동 코드의 작성과 수정 및 검증을 진행했습니다.

AI가 만든 결과를 한 번에 확정하지 않고 실제 플레이 결과, 오류 상황과 프로젝트 규칙을 기준으로
추가 요구사항을 전달하며 반복적으로 개선했습니다. 이 문서는 코드 작성 주체를 숨기기 위한 문서가
아니라, AI가 작성한 코드를 어떤 구조와 기준으로 검토할 수 있는지 보여주기 위한 설명서입니다.
